# Purpose

This document records the reasoning behind major architectural decisions made throughout the development of the Soma Digital Community (SDC).

Architecture Decision Records (ADRs) provide historical context, explain trade-offs, and help ensure future development remains aligned with the platform's long-term vision.

Each ADR should be immutable once approved. New information should result in a superseding ADR rather than rewriting history.

---

# ADR-001: Cloud Platform

## Decision

Use **Firebase** as the primary backend platform during the MVP and growth stages.

## Status

Approved

## Context

SDC requires:

* Authentication
* Realtime database
* Document storage
* File storage
* Serverless functions
* Push notifications
* AI integration
* Analytics

Firebase provides a mature managed platform with minimal operational overhead.

## Alternatives Considered

* Supabase
* AWS
* Azure
* Self-hosted PostgreSQL
* Appwrite

## Decision Drivers

* Rapid development
* Operational simplicity
* Native authentication
* Firestore scalability
* Cloud Functions
* Excellent Next.js integration
* Strong Google AI ecosystem compatibility

## Consequences

Pros

* Faster MVP delivery
* Lower DevOps burden
* Managed infrastructure
* Strong SDK ecosystem

Cons

* Vendor lock-in risk
* Firestore query limitations
* Cost management required at scale

Mitigation

Abstract business logic from Firebase-specific APIs wherever practical.

# ADR-003: AI Provider Strategy

## Decision

Remain **AI-provider agnostic**.

## Status

Approved

## Context

AI providers evolve rapidly in quality, pricing, latency, and capabilities.

Binding the platform to a single provider would increase risk and reduce flexibility.

## Decision

Implement an AI Gateway abstraction that supports multiple providers through a common interface.

## Benefits

* Lower costs
* Better reliability
* Easier provider switching
* Access to best-in-class models
* Future compatibility with proprietary Soma AI models

# ADR-004: AI Gateway

## Decision

Initially use **Vercel AI Gateway** behind SDC's internal AI Service Layer.

## Status

Approved

## Reasoning

Vercel AI Gateway accelerates development while allowing SDC to retain control through its own abstraction.

The application must never communicate directly with external providers.

Instead:

```text
Application

↓

AI Service Layer

↓

Vercel AI Gateway

↓

AI Providers
```

Long-term, Vercel AI Gateway may be replaced with the proprietary Soma AI Gateway without requiring application changes.

# ADR-005: AI Orchestration

## Decision

Implement a centralized AI Orchestrator.

## Reasoning

Different tasks require different models.

Examples:

* Business coaching
* Translation
* Video generation
* Voice generation
* Image generation

The orchestrator selects the most appropriate model based on quality, cost, speed, user plan, and availability.

# ADR-006: AI Cost Management

## Decision

Use Creator Credits instead of exposing API token costs.

## Reasoning

Users should purchase business outcomes rather than AI infrastructure.

Credits provide:

* Simplicity
* Pricing flexibility
* Internal cost abstraction
* Marketing clarity

---

# ADR-007: Cost-Aware Routing

## Decision

The AI Orchestrator must optimize for both quality and cost.

## Priority Order

1. Request validity
2. User plan
3. Required quality
4. Estimated cost
5. Provider health
6. Latency

The orchestrator should select the least expensive model that satisfies the request unless the user explicitly requests a higher quality mode.

## Decision

Examples:

AI

Billing

Social

Marketplace

Community

Analytics

# ADR-011: Configuration Over Hardcoding

## Decision

All configurable values must reside in centralized configuration.

Avoid hardcoding:

* Pricing
* Models
* Providers
* Credits
* Limits
* Features
* Prompt templates
* Routing rules

---

# ADR-012: Event-Driven Architecture

## Decision

Use asynchronous events for long-running and cross-cutting workflows.

Examples:

* Subscription changes
* AI generation completion
* Credit renewals
* Notifications
* Social media publishing
* Analytics updates

This reduces coupling and improves scalability.

# ADR-013: AI Asset Reuse

## Decision

Generated AI assets should be reusable without additional credit consumption.

Assets include:

* Images
* Videos
* Voice
* Documents
* Prompts
* Content

This improves user experience and reduces AI costs.

# ADR-014: Prompt Management

## Decision

Prompt templates shall be centrally managed, versioned, and reusable.

Prompts must never be embedded directly in UI components.

---

# ADR-015: AI Memory

## Decision

AI memory shall be contextual and user-scoped.

Persistent memory should support long-term coaching while respecting user privacy and allowing users to manage or delete stored context.

---

# ADR-016: Social Media Automation

## Decision

Scheduling and publishing do not consume Creator Credits.

Only AI-assisted content generation consumes credits.

This aligns costs with actual AI resource usage.

# ADR-019: Security by Default

## Decision

Security is a foundational requirement, not an enhancement.

Key principles:

* Least privilege
* Server-side enforcement
* Encrypted secrets
* Immutable audit logs
* Rate limiting
* Abuse detection
* Input validation
* Secure defaults

---

# ADR-020: Build vs. Buy

## Decision

Use managed services where they accelerate delivery without compromising strategic control.

Examples:

* Firebase for backend infrastructure
* Vercel AI Gateway for initial AI routing
* Third-party AI models during early growth

Retain ownership of:

* AI orchestration logic
* Business rules
* Creator Credit engine
* User experience
* Product workflows
* Proprietary business intelligence

The long-term objective is to replace strategic dependencies—such as the AI Gateway—with SDC-owned capabilities only when doing so provides a clear business or technical advantage.
